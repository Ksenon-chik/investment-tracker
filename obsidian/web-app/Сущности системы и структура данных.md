
### 1. Новые сущности

- User - пользователь
- Deal - инвестиционная сделка

### 2. Сущность user

#### Атрибуты User

- `id` — уникальный идентификатор
    
- `username` — логин пользователя
    
- `email` — электронная почта
    
- `hashed_password` — хэш пароля
    
- `created_at` — дата регистрации
    
- `is_active` — статус учетной записи
    

#### Ограничения

- `username` — уникальный
    
- `email` — уникальный
    
- пароль хранится только в хэшированном виде

### 3. Сущность deal

#### Атрибуты Deal

- `id` — уникальный идентификатор
    
- `user_id` — владелец сделки
    
- `date` — дата сделки
    
- `asset` — финансовый актив
    
- `direction` — покупка / продажа
    
- `result` — прибыль / убыток
    
- `amount` — величина прибыли или убытка
    
- `risk_reward` — соотношение прибыль / убыток
    
- `comment` — комментарий пользователя (опционально)
    
- `timeframe` — таймфрейм сделки (опционально)
    
- `created_at` — дата добавления записи

#### Ограничения

- каждая сделка принадлежит одному пользователю
    
- пользователь имеет множество сделок
    
- `amount` может быть как положительным, так и отрицательным значением

### 4. Связи сущностей

User 1 ─── * Deal
- один пользователь может иметь множество сделок
    
- сделка не может существовать без пользователя

### 5. Бизнес правила

- пользователь имеет доступ **только к своим сделкам**
    
- аналитика рассчитывается **только на основе сделок пользователя**
    
- данные одного пользователя изолированы от других
